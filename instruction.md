# Odoo-Themed UI.md (Hackathon Build)

Binding rules for every screen. Follow them exactly. Do not invent colors, fonts, radii, shadows, or new component styles. If something is missing, reuse the closest existing pattern and flag it in your reply.

Theme source: the Odoo look (odoo.com and Odoo brand assets): light surfaces, Odoo purple `#714B67` as the primary, Odoo teal `#017E84` as the secondary, Inter for all headings and body text. Structure, proportions, spacing, components, and motion are unchanged from the original UI.md.

## 0. Precedence
1. This file overrides your defaults and any generic template habits.
2. Tokens in section 3 are the only source of color, type, and radius.
3. If this file conflicts with a screenshot or with odoo.com, this file wins. odoo.com is a reference for look and feel only, not a source of copy, logos, statistics, or customer quotes.
4. Earlier exports and screenshots (dark surfaces, saffron-orange or rose accent) are retired. Replace the accent with `primary` (Odoo purple) and the dark surfaces with the light tokens in section 3.

## 1. Product character
The product is a serious, modern business-software SaaS. A buyer must feel: "this is simple, fast, and well-engineered, and it covers my whole workflow."
- Light only. Off-white page, white cards, hairline borders, one purple accent, one teal secondary. No dark mode.
- Purple means action or live state: primary button, active tab or nav item, focus, links, latest data point, "Running" or "In progress". Never decoration.
- Teal means information or the second data series. Never a second call to action.
- Borders separate surfaces, not shadows. The only shadow is `shadow-xl` on floating menus.
- Dense, precise, data-first, and calm. Mono type for ids, references, amounts in logs, and commands.
- One platform, many apps: screens are organized by business app (CRM, Sales, Inventory, Accounting, Purchase) and share one set of components. Never design a screen that looks like a different product from the others.
- India-first content: ₹ with Indian grouping (₹2,499), IST timestamps, GST at 18% in sample invoices, Chennai and Mumbai warehouses, Hindi/Tamil/Telugu partner names.
- Never playful. No mascots, confetti, emoji, or jokes in UI copy.

## 2. Anti-generic rules (no "AI-made" look)
The UI must not look like the default output of an AI site builder or a stock Odoo theme clone. Specifically:
- **No watermarks or attribution.** Nothing like "Made with / Built with / Generated by AI", no tool badges, no placeholder credits, no lorem ipsum, no "Acme" or "John Doe" data.
- **Odoo brand use.** Do not copy the Odoo logo, Odoo screenshots, or Odoo's own statistics (user counts, app counts, response times) into our UI. Write "Odoo" with a capital O and lowercase letters (never "ODOO", never "Odoos"), and only where the hackathon context requires naming it (for example "Odoo-compatible", "Odoo integration"). Never imply the product is made or endorsed by Odoo unless the team confirms it.
- **Banned visual tells:** purple/blue-to-pink gradients, any gradient on the purple accent (purple is always a flat color), gradient text, glassmorphism cards, blurred color blobs, glowing borders or shadows, neon, sparkle ✨ icons as "AI" branding, emoji used as icons, floating 3D shapes, dotted grid or noise backgrounds used as filler, rounded-everything.
- **Banned layout tells:** every section centered with the same heading, subheading, and 3 equal cards; a stats row directly under every hero; repeating the same card grid more than twice on one page; symmetrical layouts with no hierarchy. Vary the rhythm: use split layouts (text left, product right), asymmetric grids (`grid-cols-[1.2fr_1fr]`), full-width product panels, and dividers with real content.
- **Banned copy tells:** "Unlock the power of", "Revolutionize", "Seamless", "Supercharge", "Elevate", "Cutting-edge", "Next-gen", "All-in-one solution". Write specific, concrete sentences ("Turn a won deal into a sales order in one click").
- **Real product over decoration.** Hero and feature sections show real-looking product UI built from our own components (app screens, tables, charts), not abstract illustrations or stock device photos.
- **One icon set only:** Lucide-style stroke icons via Iconify, 1.75 to 2 stroke, sizes 13, 16, 18, or 20px. Never use unicode glyphs (⇪ ◌ ⧉ ✕) as icons in production. App tiles use a Lucide icon inside an `h-10 w-10 rounded-md bg-primary/15 text-primary` tile, never multicolor app icons.
- **Do not ship default component-library looks.** If using shadcn/ui or Radix, restyle fully with our tokens. Do not ship stock Bootstrap or stock Odoo backend styling.
- **No fabricated proof.** Do not invent customer logos, testimonials, statistics, certifications (SOC 2, ISO 27001), or compliance claims. Use real ones supplied by the team, or hide the block. Mark unverified data with `TODO(real data)` in code comments, never in the UI.

## 3. Tokens (Tailwind v4 `@theme`)
```css
@theme {
  --color-background: #f9fafb;        /* page */
  --color-surface: #ffffff;           /* cards, panels */
  --color-surface-raised: #f1f3f5;    /* hover rows, menus, table header */
  --color-input: #ffffff;             /* inputs, inner tiles */
  --color-border: #d8dadd;
  --color-foreground: #212529;        /* primary text */
  --color-muted: #eef0f2;             /* disabled fill, skeletons, tracks */
  --color-muted-foreground: #5f6368;  /* secondary text */
  --color-primary: #714b67;           /* Odoo purple: the only accent */
  --color-primary-foreground: #ffffff;
  --color-secondary: #e9ecef;
  --color-secondary-foreground: #212529;
  --color-success: #14825f;
  --color-warning: #9a6700;           /* amber dark enough for text on white */
  --color-error: #dc3545;
  --color-teal: #017e84;              /* Odoo secondary: info, BETA tag, chart mid-series */
  --color-gold: #e4a900;              /* compliance badges (Odoo partner gold) */

  --font-headings: "Inter";
  --font-body: "Inter";
  --font-mono: "IBM Plex Mono";

  --radius-sm: 4px;   /* checkbox, tag badge, chart bar, skeleton */
  --radius-md: 8px;   /* buttons, inputs, tiles, tables, menus */
  --radius-xl: 24px;  /* cards, sections, modals */

  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);
}
```
- Tints: `bg-{c}/10` (alerts), `bg-{c}/15` (pills), `border-{c}/30` (pills). `{c}` is success, warning, error, or primary.
- Never hardcode hex in components. Chart SVG strokes may use the primary hex `#714b67`.
- Contrast on light at least 4.5:1. `text-muted-foreground` is for secondary text only. Text on `bg-primary` is at least 14px, medium or bold, always `text-primary-foreground`.
- **Purple as text:** `text-primary` on `background` and `surface` is about 7:1, so it may be used for headline highlights, links, active nav labels, and KPI values. Links are `text-primary` and underlined.
- **Teal as text:** `text-teal` is about 4.9:1 on white, so use it only for medium or bold text and for non-text marks. Never use teal for body copy or buttons.
- **Brand gray:** Odoo's `#8F8F8F` fails 4.5:1 as text. It is not a token. Use `text-muted-foreground` for secondary text and `border` for lines.
- **Purple vs error:** purple is brand and action, red is failure and danger. Never use `primary` to signal an error, and never use `error` for emphasis. Failed pills always carry an icon and the word "Failed".
- **Name mapping (landing export to tokens):** `saffron` and `rose` (retired accents) = `primary` (purple), `ink` = `foreground`, `ink-soft` = `surface`, `ink-line` = `border`, `cream` = `background`, `leaf` = `success`. Map by role, never by the old hex values. Ignore `sand` and any leftover dark-theme values (`#0b0d12`, `#151a24`, `#1d2432`).

## 5. Layout and spacing
- 4px Tailwind scale. Card padding `p-5` to `p-7`. Section gap `gap-5` or `gap-6`. Inner gap `gap-4`.
- Containers: `max-w-[1360px] px-8` for app pages, `max-w-6xl px-10` for landing sections, `max-w-5xl` for hero copy.
- **Card:** `rounded-xl border border-border bg-surface overflow-hidden`. Header `px-6 py-4 border-b border-border`, body `p-6`.
- **Inner tile:** `rounded-md border border-border bg-input p-4` (or `p-5`).
- Landing sections have generous vertical rhythm: `py-24` to `py-32` between major sections.
- Alternate section backgrounds between `background` and `surface` (with a `border-y border-border`) to separate landing sections without shadows.

## 6. Components

### Buttons
Base `rounded-md text-sm font-medium`. Sizes: sm `px-3 py-1.5`, default `px-4 py-2`, lg `px-6 py-3`.
| Variant | Default | Hover | Disabled |
|---|---|---|---|
| Primary | `bg-primary text-primary-foreground` | `opacity-85` | `bg-muted text-muted-foreground` |
| Secondary | `bg-secondary text-secondary-foreground border border-border` | `bg-surface-raised` | `bg-muted text-muted-foreground` |
| Ghost | `border border-border text-foreground bg-surface` | `bg-surface-raised` | `text-muted-foreground opacity-50` |
| Destructive | `bg-error text-white` | `opacity-85` | `bg-muted text-muted-foreground` |
- Icon button 40x40, `rounded-md`, 18px icon.
- Pressed: `scale-[0.98]`. Loading: replace label with a 16px spinner, keep width, disable.
- One primary button per view area.

### Inputs
Base `rounded-md border border-border bg-input px-3 py-2.5 text-sm`. Label above: `mb-1.5 text-sm font-medium`.
- Focus: `border-2 border-primary`, no glow. Error: `border-error` plus `mt-1 text-xs text-error` message that says how to fix it.
- Select: same box, chevron icon right. Textarea: same box, muted placeholder.
- Checkbox `h-5 w-5 rounded-sm` (checked: `bg-primary`, white check icon). Radio `h-5 w-5 rounded-full` (selected: `border-2 border-primary` with a `h-2 w-2 bg-primary` dot). Toggle `h-6 w-11 rounded-full` (on: `bg-primary`, off: `bg-muted`, knob `h-4 w-4 bg-white`, with a `border border-border` on the off track so it stays visible on light).
- File upload: `rounded-md border border-dashed border-border bg-input p-5 text-center`, icon tile `h-10 w-10 rounded-md bg-surface-raised`, hint in `text-xs text-muted-foreground`.
- All interactive elements get a visible `focus-visible` style: 2px `primary` outline, 2px offset.

### Badges and status pills
Pill: `rounded-full border px-3 py-1 text-xs font-medium` plus the tint pattern and a leading icon.
- Running (primary), Queued (warning), Completed (success), Failed (error), Neutral (`bg-muted text-muted-foreground border-border`).
- Business states reuse the same five: Draft = Neutral, Quotation sent = Queued, Confirmed = Running, Done or Paid = Completed, Cancelled or Overdue = Failed.
- Tag badges: BETA `rounded-sm bg-teal text-white px-2 py-1 text-xs`. Compliance `rounded-sm bg-gold/20 border border-gold/50 text-foreground px-2 py-1 text-xs`. Show compliance badges only if true.
- Status is always icon plus text, never color alone. Running uses a pulsing dot or spinner icon, Failed uses an alert icon, so the two never rely on purple vs red to be told apart.

### Tabs, breadcrumbs, pagination, progress
- Tabs: row with `border-b border-border text-sm`, tab `px-3 pb-2`. Active `border-b-2 border-primary font-medium`, inactive `text-muted-foreground`. The active underline slides between tabs (see Motion).
- Breadcrumbs: `text-sm text-muted-foreground`, `/` separators, parent and current in `text-foreground`.
- Pagination: arrows `rounded-md border border-border px-2.5 py-1`, current page `bg-primary text-primary-foreground rounded-md px-2.5 py-1`.
- Progress: track `h-2 rounded-full bg-muted`, fill `rounded-full`: `bg-primary` in progress, `bg-success` healthy or complete, `bg-warning` at 80% quota or more, `bg-error` at 95% or more.

### Table
- Wrapper `overflow-hidden rounded-md border border-border`. Header `bg-surface-raised px-4 py-2.5 font-mono text-xs uppercase tracking-widest text-muted-foreground`.
- Rows `bg-surface px-4 py-3 text-sm border-t border-border`. Hover `bg-surface-raised`. Selected `bg-primary/10 border-l-2 border-l-primary`.
- Row actions: `•••` icon button, opens a dropdown. Numeric columns right-aligned, mono, `tabular-nums`.
- Always provide empty, loading (skeleton rows), and error states. On small screens the table scrolls horizontally inside `overflow-x-auto`.

### Overlays
- **Modal:** `rounded-xl border border-border bg-surface p-5`, title `font-headings text-lg font-semibold`, description `text-sm text-muted-foreground`, actions right-aligned `gap-2` (Cancel ghost, confirm primary or destructive). Backdrop `bg-foreground/40`.
- **Dropdown:** `w-48 rounded-md border border-border bg-surface p-2 shadow-xl`, items `px-2 py-1.5 text-sm rounded-sm` (hover `bg-surface-raised`), destructive item `text-error`.
- **Tooltip:** `rounded-md bg-foreground text-background px-2 py-1 text-xs`.
- **Toast / alert:** `rounded-md border border-{c}/30 bg-{c}/10 px-3 py-2.5 text-sm`, semantic icon, bold lead phrase plus muted detail. Toasts auto-dismiss after 5s, errors persist. Never block the page with a toast.
- Destructive confirmations name the object ("Delete S00042?"). Irreversible and high-impact actions require typing the resource name.

### Feedback
- Empty state: centered in a tile, icon tile `h-12 w-12 rounded-xl bg-surface-raised`, title `text-sm font-medium`, one helpful line, one primary action.
- Loading: use skeletons (`bg-muted rounded-sm`, shimmer) for page and table loads. Use a spinner (`h-6 w-6 border-2 border-muted border-t-primary`) only for short in-place actions.
- Error page or block: state what happened, what to do, and a retry action. Include a request id in mono when relevant.

### Cards and KPIs
- KPI tile: label `text-sm text-muted-foreground`, value `font-headings text-3xl font-bold tabular-nums`, delta pill (`bg-success/15 text-success rounded-full px-2 py-0.5 text-xs`), footnote `text-xs text-muted-foreground`.

## 7. Charts and code
- Bars `rounded-sm`: `primary` default, `warning` for attention, `border` color for neutral or baseline. Landing app mock: older periods `border` color, mid periods `teal`, latest period `primary`.
- Line: stroke primary, 3px, round caps, end-point dot r=5. Grid lines `border` at low opacity. Axis labels `text-xs text-muted-foreground` mono.
- Do not use `error` and `primary` as two series in the same chart. Use `teal` as the second series.
- Tooltips on charts reuse the dropdown surface style. Always include a legend when there is more than one series, and never rely on color alone.
- Terminal and code: `bg-surface-raised border border-border rounded-md font-mono text-xs leading-relaxed text-foreground`, header row with the command and a Copy chip (`bg-surface border border-border rounded-sm px-2 py-0.5`). Success lines `text-success`, errors `text-error`, progress `text-primary`. Copy gives a 1.5s "Copied" confirmation.

## 8. Motion system
Motion must feel precise and quiet, like a premium business tool. Never playful.
- **Library:** Motion (framer-motion) for component and scroll animation, unless the project already uses another. Animate only `transform` and `opacity`, never width, height, top, or left.
- **Tokens:** micro 150ms, UI 250ms, reveal 600 to 800ms. Easing `--ease-out` for entrances, `--ease-in-out` for position changes. No springs with overshoot, no bounce.
- **Micro-interactions (everywhere):** buttons `scale-[0.98]` on press; card hover `translateY(-2px)` plus `border-color` shifting to `primary/40` (no glow); row hover background fade 150ms; tab underline slides; toggle knob slides; checkbox check draws in; focus ring fades in.
- **Overlays:** modal fades and scales 0.98 to 1 (250ms); dropdown and tooltip fade with a 4px offset (150ms); drawer slides from the edge (300ms); toast slides up and fades.
- **Data:** charts draw or grow on first view only (bars from 0, 600ms, 40ms stagger); KPI numbers count up once (800ms); skeleton shimmer is slow (1.6s loop); the Running status dot pulses softly (2s loop). These and spinners are the only infinite animations allowed.
- **In-app (dashboard):** keep motion to micro-interactions, overlays, skeletons, and data updates. No scroll-triggered reveals inside the app.
- **Banned:** parallax heavy effects, typewriter text, cursor followers, particle or aurora backgrounds, auto-rotating carousels, looping decorative animations, scroll-jacking that hijacks the wheel or breaks the native scrollbar.
- **Accessibility:** under `prefers-reduced-motion: reduce`, disable all transforms, scroll effects, and count-ups. Keep simple opacity fades at most, and turn off Lenis.

## 9. Landing page blueprint
**Smooth scroll**
- Use Lenis on the landing page only (never in the app): `duration` about 1.1, easing `--ease-out`, `smoothWheel` on, touch behaves natively. Anchor links scroll with an offset equal to the sticky nav height. Disable for reduced-motion users.

**Scroll reveals**
- Each section's content fades and rises (`opacity 0 to 1`, `translateY 24px to 0`, 700ms, `--ease-out`). Trigger once at about 15% visibility. Stagger children 60 to 80ms. No re-triggering on scroll up.
- Limit: at most one reveal per content block. Do not animate every element individually.

**Structure (in order)**
1. **Sticky nav:** `px-8 py-5`. Transparent at top, then `bg-background` with a bottom `border-border` after 8px of scroll (color fade 200ms). Logo, 5 links, Sign in (ghost), primary CTA ("Start free" or similar verb). Collapses to a menu below `lg`.
2. **Hero:** eyebrow pill (release note with a live dot), headline with the last line in `text-primary`, 2-line subcopy in `text-muted-foreground`, CTA pair (primary plus ghost), 3 short trust ticks. Stagger in on load (eyebrow, headline, copy, CTAs, 80ms apart). Consider a split hero: copy left, product panel right.
3. **Product app mock:** window chrome (3 dots in `border` color), 3-panel layout `grid-cols-[220px_1fr_220px]`: app or pipeline list (CRM, Sales, Inventory), chart with a log line, live metrics. Bars grow on load, metrics count up, status dot pulses. Subtle scroll-linked translate (max 24px) is allowed here only.
4. **Trust strip:** only real customer logos or partners, `opacity-60`, hidden if none.
5. **Feature section:** vary layout from the hero. Use a split layout with product UI beside text, then one compact card grid with icon tile `h-10 w-10 rounded-md bg-primary/15 text-primary`. Do not use the same card grid twice in a row.
6. **Proof / metrics:** real numbers only, in `font-headings text-3xl` inside bordered tiles. Count up once.
7. **Security and data ownership:** data residency, access controls, audit logs, export of your own data, and only compliance badges that are real. Link to a security page.
8. **Pricing:** 3 columns. Featured plan uses `bg-surface` with a "Most popular" `bg-primary` tag. Prices in ₹, Indian grouping, clear billing unit (per user per month), a one-line audience, 4 to 5 real features, a bottom-aligned CTA. The featured card gets a `border-primary` highlight, not a glow.
9. **Final CTA + footer:** CTA band on `surface` with a top and bottom `border-border` and one primary button. Footer on `bg-foreground text-background` with `text-background/70` links: 4 link columns, logo, one factual line, legal and status links, copyright. No AI, Odoo, or builder attribution.
